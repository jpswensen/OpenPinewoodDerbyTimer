Project Context:
This project modernizes a Pinewood Derby Timer system, creating a complete race management
solution with a modern web interface (FastAPI + React), SQLite database, and updated ESP32
firmware. The system supports 4–8 lane configurations and both USB serial and WiFi/TCP + mDNS
communication with the timing hardware.

Reference Implementation (read-only reference — do NOT modify):
- ../SunnysidePWDTimer/Python/ — Previous Python/PyQt5 implementation
  - pwdtimer.py — main UI and flow
  - pwdtimer_communications.py — serial/TCP comms
  - racefiles.py — Racer/Group/RaceData models
  - *_widget.py — UI widgets for major screens
- ../SunnysidePWDTimer/*.cpp, *.h — Original C++/Qt implementation (4-lane)
- ../SunnysidePWDTimer/Arduino/ — firmware variants
- ../SunnysidePWDTimer/Board/ — schematics/PCB designs and parts list

Communication Protocol:
- Status frame: $state,startTime,currentTime,numLanes,endTime[0],endTime[1],...*
- Times are microseconds (μs)
- States: RESET=1, SET=2, IN_RACE=3, FINISHED=4
- Commands: RESET, SET_LANES:n, ARM
- Transports: USB serial OR TCP sockets; mDNS discovery when on same LAN

Hardware Pin Mapping (ESP32 8-lane target):
- Lane 1: GPIO12    Lane 5: GPIO25
- Lane 2: GPIO14    Lane 6: GPIO33
- Lane 3: GPIO27    Lane 7: GPIO32
- Lane 4: GPIO26    Lane 8: GPIO23
- Start Gate: GPIO22
- WiFi Mode Select: GPIO21

Workflow:
1. Find the earliest task in plans/prd.json with passes: false.
2. Implement the task thoroughly, following existing patterns.
3. Add/extend tests and run them.
4. Update plans/prd.json to mark the item passes: true.
5. Append an entry to progress.txt using the template below.
6. Commit with conventional commits: feat/fix/test/docs/refactor/chore.
